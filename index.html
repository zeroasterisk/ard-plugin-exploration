🎯 The 7 Real-World Scenarios

  • 1 Scenario 1 (Tier 0 Pure Discovery): Zero-auth counterpoint. User asks for security design & SQL tuning ➜ OpenCode recommends Tier 0 skills (no auth, no GCP prompts).
  • 2 Scenario 2 (Respectful Opt-Out Flow): User asks for BigQuery ➜ OpenCode asks "Do you want to login to GCP?" ➜ User replies "No with an opt out" ➜ GCP silenced permanently.
  • 3 Scenario 3 (Live Human OAuth & Execution): User replies "Yes" ➜ Completes browser OAuth login ➜ OpenCode detects active ADC & autonomously runs live BigQuery SQL query.
  • 4 Scenario 4 (Path A: API Key Only): Environment has GEMINI_API_KEY ➜ Tier 1 Gemini developer tools unlocked directly with zero GCP login prompts.
  • 5 Scenario 5 (Path B: Enterprise SA Mount): Environment has GOOGLE_APPLICATION_CREDENTIALS ➜ OpenCode passively detects active service account on Turn 1 with zero prompts.
  • 6 Scenario 6 (Path C: Changing Mind): Previously opted-out user asks to log in ➜ ARD seamlessly flips preference to allowed and guides onboarding.
  • 7 Scenario 7 (Complete Automated E2E Suite): Real-time containerized execution of all 7 E2E test scenarios and 13 unit tests.

🔑 Why This Solves Developer & Detractor Concerns

• Zero Account Prerequisite: Over 60% of entries in the catalog are standalone Tier 0 skills that provide instant local value without any account or API key.

• Strict User Agency: When a user opts out, the agent permanently records the preference and never nags about cloud accounts again.

• Tier 1 API Key Direct Enablement: Developers with only Gemini API keys get immediate access to models and skills without GCP onboarding.

• Enterprise Headless Friendly: Automated service accounts mount passively without interactive prompts.

• Pre-Execution Clarity: Proactive status: needs_onboarding metadata prevents blind 401/403 runtime crashes.
